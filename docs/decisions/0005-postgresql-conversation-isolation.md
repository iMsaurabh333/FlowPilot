# ADR 0005: PostgreSQL Conversation Ownership and Trial Privacy Testing

- Status: Accepted
- Date: 2026-08-16

## Context

Chat history must survive application restarts and remain private to the authenticated BTP user. The trial marketplace provides the `postgresql-db` service with a `trial` plan, but the current trial account cannot provide a second real user for a deployed two-user test.

## Decision

Use the SAP BTP `postgresql-db` trial service for the first persistent-chat milestone. Keep the API stateless and use PostgreSQL for the conversation catalog and LangGraph checkpoint state.

Conversation ownership is based only on the validated XSUAA tenant and subject claims. The browser supplies a conversation UUID but never an owner. Every conversation lookup combines the UUID with the server-derived owner identity before graph state is accessed.

Apply layered isolation:

1. API authorization validates the XSUAA token and required scope.
2. Repository methods require an authenticated identity object rather than independent owner strings.
3. Conversation queries include tenant and subject ownership.
4. PostgreSQL row-level security protects application-owned conversation records using transaction-local identity settings.
5. LangGraph thread identifiers are generated by the server and resolved only after the owned conversation record is found.
6. Logs contain opaque conversation and request identifiers, not message contents or identity claims.

The initial context sent to the model is intentionally bounded. The model sees the system instructions and recent conversation messages within the configured context budget, not the user's complete historical archive.

Because a second deployed identity is unavailable, use three levels of evidence:

- unit tests with two distinct authenticated-user fixtures;
- PostgreSQL integration tests proving that identity A cannot list, read, or write identity B's rows or thread;
- a deployed single-user smoke test proving authentication, persistence after refresh, and denial for an unknown or non-owned conversation ID.

A real two-user BTP smoke test remains a release limitation and must be performed when an environment with two identities becomes available. The project must not claim that test has passed in the trial environment.

## Consequences

- The current trial environment can provide strong automated isolation evidence without fabricating a second cloud user.
- Database migrations and PostgreSQL integration tests become required delivery gates.
- LangGraph checkpoint access must never occur before conversation ownership is established.
- A real two-identity deployed test remains required before production use.
- Retention, export, and deletion policies must cover both conversation records and checkpoint state.
